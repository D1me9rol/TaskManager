# Task Manager REST API

## Описание проекта

Task Manager — REST API для управления задачами, разработанное на Java и Spring Boot с использованием базы данных H2.

Приложение позволяет создавать, просматривать, редактировать и удалять задачи, изменять их статусы, искать задачи по названию, фильтровать и сортировать список. Также реализовано сохранение истории событий для каждой задачи.

Удаление задач выполняется логически (soft delete): удалённые задачи не отображаются в обычном списке и не доступны для получения и редактирования, однако информация о них и история событий сохраняются в базе данных.

## Запуск приложения
Открыть терминал в корневой директории проекта и выполнить команду:

```bash
mvn spring-boot:run
```

После запуска приложение будет доступно по адресу:

http://localhost:8080

Все команды необходимо выполнять из корневой директории проекта.

## Запуск автоматизированных тестов

Для выполнения всех автоматизированных тестов необходимо открыть терминал в корневой директории проекта и выполнить команду:

```bash
mvn test
```

В проекте используются JUnit 5, Spring Boot Test и MockMvc.

Автоматизированные тесты проверяют основные операции API:

- создание задач;
- получение списка и отдельных задач;
- редактирование задач;
- изменение статусов;
- удаление задач;

Для тестирования используется отдельная база данных H2 в оперативной памяти, поэтому тесты не изменяют основную базу данных приложения.

## Документация API

Документация API доступна через Swagger UI:

http://localhost:8080/swagger-ui.html

Swagger позволяет просматривать доступные методы API и отправлять запросы непосредственно через браузер.

## База данных

В проекте используется H2 Database.

Основные параметры подключения:

| Параметр | Значение |
|---|---|
| JDBC URL | `jdbc:h2:file:./data/taskdb;DB_CLOSE_ON_EXIT=FALSE` |
| Driver Class | `org.h2.Driver` |
| Username | `sa` |
| Password | отсутствует |

Для доступа к консоли H2 необходимо запустить приложение и открыть:

http://localhost:8080/h2-console

В форме подключения необходимо указать параметры, приведённые выше.

База данных хранится в файловом режиме. При первом запуске приложения необходимые таблицы создаются автоматически с помощью `schema.sql`.

## Основные API-методы

| Метод | Endpoint | Описание |
|---|---|---|
| POST | `/api/tasks` | Создание задачи |
| GET | `/api/tasks` | Получение списка задач |
| GET | `/api/tasks/{id}` | Получение задачи по ID |
| PUT | `/api/tasks/{id}` | Редактирование названия и описания задачи |
| PATCH | `/api/tasks/{id}/status` | Изменение статуса задачи |
| DELETE | `/api/tasks/{id}` | Удаление задачи |
| GET | `/api/tasks/{id}/history` | Получение истории событий задачи |

### Параметры получения списка задач

Для метода `GET /api/tasks` предусмотрены следующие query-параметры:

| Параметр | Описание | Допустимые значения |
|---|---|---|
| `title` | Поиск по названию задачи | Любая строка |
| `status` | Фильтрация по статусу | `NEW`, `IN_PROGRESS`, `DONE` |
| `sortBy` | Поле сортировки | `TITLE`, `CREATED_AT` |
| `direction` | Направление сортировки | `ASC`, `DESC` |

Если параметры сортировки не указаны, используются значения по умолчанию: `CREATED_AT` и `DESC`.

Поиск по названию выполняется без учёта регистра и допускает совпадение по части названия.

Пример запроса:

```http
GET /api/tasks?title=Отчет&status=NEW&sortBy=TITLE&direction=ASC
```

### Пример создания задачи

Запрос:

```http
POST /api/tasks
Content-Type: application/json
```

Тело запроса:

```json
{
    "title": "Изучить Java",
    "description": "Пройти основы Java"
}
```

При успешном создании сервер возвращает `201 Created` и объект созданной задачи.

Статус и дата создания назначаются автоматически на стороне сервера.

### Пример изменения статуса задачи

Запрос:

```http
PATCH /api/tasks/1/status
Content-Type: application/json
```

Тело запроса:

```json
{
    "status": "IN_PROGRESS"
}
```

Допустимые статусы задачи:

- `NEW` — новая задача;
- `IN_PROGRESS` — задача в процессе выполнения;
- `DONE` — задача выполнена.

## История событий

Для каждой задачи сохраняются следующие события:

- `CREATED` — создание задачи;
- `UPDATED` — изменение данных задачи или её статуса;
- `DELETED` — удаление задачи.

Каждое событие содержит свой тип и время возникновения.

История событий доступна по адресу:

```http
GET /api/tasks/{id}/history
```

При логическом удалении задачи её запись и история событий остаются в базе данных.

## Обработка ошибок

В приложении реализована обработка основных ошибок:

| HTTP-статус | Описание |
|---|---|
| `400 Bad Request` | Некорректные входные данные или ошибка валидации |
| `404 Not Found` | Задача с указанным ID не найдена |
| `201 Created` | Задача успешно создана |
| `200 OK` | Запрос успешно выполнен |
| `204 No Content` | Задача успешно удалена |

Ошибки валидации обрабатываются централизованно с помощью `GlobalExceptionHandler`.
